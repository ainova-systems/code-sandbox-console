## What & why

AI skills and rules that drive sandboxes from the CLI (validated against a real
consumer: `Intelligence/rules/sandbox.md` + `sandbox-*` skills in a host repo)
currently re-encode the extension's entire model as prose: instance naming
`<name>-<key>-<id>`, identity bootstrap for fresh clones, host→sandbox path
translation, the build→save→`template load`→recreate pipeline, clone-runner
lifecycle with guarded removal, and the secret-sourcing chain. That knowledge is
duplicated and drifts — every extension change invalidates hand-maintained rules.

The extension owns this model. It can export it as a **generated, committed bash
script** — `.sandbox/scripts/sbx.sh` with subcommands — so skills shrink to thin
one-line calls and raw-`sbx` knowledge survives only as a fallback for copies
without the script.

## What changed

- **Generation.** On activation and after each form save the extension writes
  `.sandbox/scripts/sbx.sh` when missing or outdated. Header:
  `generated by Sandbox Console v<X> — do not edit` plus a content hash of the body.
  An on-disk script whose body matches its header hash (unmodified) is refreshed
  silently on version change; a mismatch (manual edits despite the header) is never
  clobbered silently — the extension warns and offers an explicit overwrite.
- **Deterministic and recipe-independent.** The script derives everything at runtime
  from `.sandbox/config.yaml` + `.sandbox/identity.yaml` (including the
  missing-identity bootstrap for fresh clones) and contains no secrets and no
  project-specific values. Its content therefore depends only on the extension
  version: git noise is limited to extension upgrades, and recipe edits never require
  regeneration.
- **Bash deliberately.** Secret values flow only through bash pipes — piping from
  PowerShell corrupts stored secrets with a BOM (field-verified by the consumer
  rules; the proxy then 401s every call). On Windows the script targets Git Bash;
  `sbx` is resolved like `sbxPath()`: PATH first, then
  `$LOCALAPPDATA/DockerSandboxes/bin/sbx.exe`.
- **Subcommand surface.** Core (committed first): `name [key]`, `status`,
  `rebuild [key]`, `task <key> "<prompt>" [--bg]` (headless `claude -p`, log-file
  convention, `total_cost_usd` in json mode), `runner-create <slug>`,
  `runner-rm <runner>` (guarded), `secret-github [target]` (consumes the spec 006
  chain: project blob → shared blob → env var). Candidates (cheap aliases once the
  core exists): `create`/`connect`/`stop`/`rm`/`exec`, `runner-dispatch`/
  `runner-log`/`runner-fetch`, `runners`.
- **Dynamic sandboxes from the recipe.** `runner-create <slug>` instantiates the
  recipe's `default: true` entry (or a given key) as an **ephemeral** instance
  `<name>-<key>-<id>-p<slug>`: agent, image (already in the sbx template store from
  Rebuild), secret names and resource caps come from the recipe; isolation is
  `--clone`; the instance is **never written back into the recipe**. Runners stay
  discoverable by name prefix (`runners`), and `runner-rm` refuses while the runner's
  branch is neither pushed nor fetched.

## Decisions

- **Generation is one-way: the extension never executes the generated script.** A
  committed file is repo-controlled input; an extension that runs it on open/connect
  would hand arbitrary code execution to any cloned repo. The UI keeps its typed
  TypeScript paths (`sbx.ts`/`ops.ts`); parity is enforced at the *generator* — the
  script template lives beside `sbx.ts` and is built from the same constants
  (naming, pipeline, flags), so drift is a compile-time concern, not a runtime one.
- Runtime derivation over baked values: a committed script must work in clones and
  copies whose `identity.yaml` differs, and must survive recipe edits without
  regeneration.
- YAML parsing in bash covers the canonical shape the form writes (documented
  limitation; exotic hand-written YAML is out of scope — the form normalises on save).
- The ephemeral-runner name suffix `-p<slug>` is the discovery contract; the
  extension's Explorer may later surface runners as read-only children of their
  recipe sandbox.
